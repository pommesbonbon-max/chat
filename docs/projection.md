# Система координат и геопривязка

## Статус точности

Atlas, Satellite и Roadmap получены из [Flamm64/GTA-V-World-Map](https://github.com/Flamm64/GTA-V-World-Map). Для каждого стиля поставляются уровни `0–5` исходной пирамиды `0–7`. Отрисовка тайлов сохраняет пропорции; перевод игровых координат опирается на общественную калибровку и обозначается `calibration: 'community'`.

Источник коэффициентов — комментарии [oyuh/w3w-map/src/lib/w3w.ts](https://github.com/oyuh/w3w-map/blob/master/src/lib/w3w.ts). README этого проекта ссылается на набор тайлов Flamm64. Это не исходные метаданные Rockstar и не независимая оценка погрешности. Поэтому точность положения игровых объектов 1:1 ещё не подтверждена.

Карта использует плоские игровые координаты. Географические проекции EPSG:3857 и WGS84 здесь не применяются. Игровая координата `z` обозначает высоту и не участвует в плоской проекции. Масштаб Leaflet далее обозначается `zoom`, чтобы отличать его от высоты.

## Оси и полотно

| Система | Горизонтальная ось | Вертикальная ось | Начало |
| --- | --- | --- | --- |
| Игровые координаты | `x` вправо | `y` вверх | Игровой ноль |
| Пиксели исходника | `u` вправо | `v` вниз | Верхний левый угол |
| Тайлы XYZ | столбец вправо | строка вниз | Верхний левый угол уровня |

| Параметр | Значение |
| --- | --- |
| Полотно поставляемого уровня `5` | `8192 × 8192` пикселя |
| Размер тайла `T` | `256 × 256` пикселя |
| Размер сетки уровня `5` | `32 × 32` тайла |
| Соотношение сторон полотна | `1:1` |
| `xmin` | примерно `−9655.765407554672` |
| `xmax` | примерно `10702.087475149106` |
| `ymin` | примерно `−8013.916500994037` |
| `ymax` | примерно `12343.936381709742` |

Границы рассчитаны обратным преобразованием углов всего полотна. Они включают океан и не означают подтверждённые пределы игрового мира или плотную рамку вокруг суши. Квадратность полотна не задаёт форму побережья.

## Коэффициенты общественной калибровки

Исходная формула рассчитана для полотна `32768 × 32768` на уровне `7`:

```text
u7 = 1.6096 × x + 15541.92
v7 = −1.6096 × y + 19868.8
```

Уровень `5` в четыре раза меньше по каждой оси:

```text
u5 = 0.4024 × x + 3885.48
v5 = −0.4024 × y + 4967.2

x = (u5 − 3885.48) / 0.4024
y = (4967.2 − v5) / 0.4024
```

Масштаб одинаков по обеим осям: `0.4024` пикселя на игровую единицу на уровне `5`. Игровой ноль находится в точке `(3885.48, 4967.2)` пикселя, а не в центре квадратного полотна. Границы выше получены подстановкой `u5, v5 ∈ [0, 8192]`; их десятичная запись не означает соответствующую точность исходной калибровки.

## Общая осевая проекция ядра

Для изображения без поворота:

```text
sx = W / (xmax − xmin)
sy = H / (ymax − ymin)

u = offsetX + (x − xmin) × sx
v = offsetY + (ymax − y) × sy

x = xmin + (u − offsetX) / sx
y = ymax − (v − offsetY) / sy
```

`W, H` — размер изображения на родном уровне; `offsetX, offsetY` — его поля внутри тайлового полотна. Для текущего Atlas поля равны нулю, а `sx = sy = 0.4024`. Ядро проверяет одинаковый масштаб по обеим осям и отклоняет конфигурации, растягивающие карту.

Координаты описывают непрерывные границы полотна. Последний адресуемый пиксель уровня `5` имеет индекс `8191`, а точка `(8192, 8192)` лежит на внешней границе. Для привязки к центрам пикселей нужно отдельно учитывать принятую конвенцию.

## Масштабы и XYZ

Для полного квадратного полотна размер на уровне `zoom` равен `T × 2^zoom`. Переход от родных пикселей уровня `5`:

```text
factor = 2^(zoom − 5)
uZoom = u5 × factor
vZoom = v5 × factor

tileX = floor(uZoom / T)
tileY = floor(vZoom / T)
```

На уровне `5` допустимые индексы тайлов — `0…31`. Точки на правой и нижней внешней границе не создают дополнительный столбец или строку `32`.

| `zoom` | Полотно, пикселей | Пикселей на игровую единицу | Тайлов на уровне |
| --- | --- | --- | --- |
| 0 | 256 | 0.012575 | 1 |
| 1 | 512 | 0.02515 | 4 |
| 2 | 1024 | 0.0503 | 16 |
| 3 | 2048 | 0.1006 | 64 |
| 4 | 4096 | 0.2012 | 256 |
| 5 | 8192 | 0.4024 | 1024 |

В каждом слое 1365 тайлов, всего 4095. При увеличении выше `maxNativeZoom = 5` Leaflet увеличивает готовые тайлы; новые детали при этом не появляются. Уровни `6–7` исходных архивов в текущую поставку не включены.

Leaflet получает игровые координаты в порядке `[y, x]`: `lat` используется как игровая вертикаль, `lng` — как игровая горизонталь. Расширение `CRS.Simple` задаёт собственную трансформацию. На уровне `zoom = 0`:

```text
u0 = 0.012575 × x + 121.42125
v0 = −0.012575 × y + 155.225
```

Затем Leaflet умножает результат на `2^zoom`. Вертикальная ось инвертируется ровно один раз.

## Независимая проверка точности

Нужны контрольные точки с известными игровыми координатами и однозначным положением на исходнике. Проверять следует центр карты и её края, используя дополнительные точки, не участвовавшие в подборе коэффициентов. Ошибку нужно записать в пикселях исходника и игровых единицах.

При необходимости общего аффинного преобразования:

```text
u = a × x + b × y + c
v = d × x + e × y + f
```

Для определения шести коэффициентов нужны как минимум три неколлинеарные пары точек; дополнительные пары позволяют оценить погрешность. Текущее ядро поддерживает осевую проекцию с полями. Поворот и сдвиг осей потребуют отдельного расширения.

Atlas, Satellite и Roadmap используют одну геопривязку и тайловую сетку. Визуально проверены побережье, Alamo Sea, аэродром и несколько городских развязок на одинаковых адресах тайлов. Это проверка совмещения изображений; она не измеряет абсолютную погрешность игровых координат.

## Кадрирование

`viewPixelBounds` задаёт начальный вид вокруг острова в пикселях исходного полотна на `nativeZoom`. Это только кадрирование: координаты, тайлы и полный `worldBounds` сохраняются. Поля океана доступны при перемещении и отдалении.
